SU LinkHub v0.13.6.26
====================

本版为软装代/真切换与内存生命周期专项修复，基于 v0.13.6.25。

1. 真模型热缓存改为“会话驻留 + 生命周期回收”
   - 代理→真：同款高模只加载一次，后续直接复用。
   - 真→代理：只切回六视图 Definition，不同步删除高模。
   - 避免同一批家具反复代/真切换时 definitions.load 叠加与延迟清理卡死。

2. 发布不再同步清理高模
   - 删除发布前的真模型 Definition 清理。
   - 发布 commit 成功后只做轻量“可回收”标记。
   - 真正回收延迟到发布完成后的空闲期，用户操作时自动暂停。
   - 每个 UI 回调只处理一个 Definition；重型步骤自动延长下一次间隔。

3. 精准回收，不扫描整个 model.definitions
   - 仅处理 LinkHub 本会话实际加载并记录的 full Definition。
   - Definition 图按“一个节点/一帧”增量发现和删除，不一次递归整棵树。
   - 六视图代理 Definition 永远受保护，不参与高模回收。
   - 同一高模被多个空间共用时，只有所有关联空间均进入可回收状态且没有真模型实例才删除。

4. LRU/压力保护
   - 默认保留最近 3 个空间或 72 个顶层高模 Definition 的热缓存。
   - 超过上限时只淘汰最久未使用、当前无真模型实例的缓存。
   - 当前正在编辑空间永远不被后台回收。

5. 模型库路径项目固定优先
   - 已连接协同项目时，项目 JSON 中的 soft_model_root 优先于本机会话偏好。
   - 解决“代理→真能切，真→代理却因路径没恢复而识别失败”的不对称问题。
   - 本地/项目均无可用路径时继续给出明确提示，不再误报为代理模型本身损坏。

6. 模型库索引内存优化
   - 并发写保护的读取基线改为 JSON 字符串快照，而不是长期保留第二整套 Hash/Array 深拷贝。
   - 保留旧热重载基线兼容。

7. 热重载一致性
   - 热重载缓存 schema 升至 6，并兼容接入 schema 5。
   - 继续保留六视图代理会话缓存，同时带回真模型驻留记录。

说明：
- 发布成功后不会为了“回内存”阻塞发布按钮；回收只有在持续空闲时才执行。
- SketchUp/Undo/native allocator 可能保留部分高水位，因此验收重点是“反复代/真切换不再阶梯式无限上涨”，而不是每次切回代理都必须立刻回到初始 Commit。
