SU LinkHub v0.13.6.18
====================

本版重点：彻底封住“待更新/待载入空间仍可进入编辑并覆盖新版本”的入口，并新增隔离式“强制解锁”历史取物模式。

1. 普通修改必须是已验证最新版本
- 顶部编辑按钮不再只判断“本机有空间实例 + 共享 SKP 存在”。
- 必须同时满足：共享文件存在、当前已载入实体通过最新快照验证、共享 revision/signature 与已载入版本一致。
- 待载入、待更新、待验证更新、版本待核对、共享版本更旧等状态全部不能进入普通修改。
- edit_space_model 后端也执行实时前置校验，因此即使旧 UI、快捷入口、双击或其他入口误调用，也不能绕过。
- 取得协作锁后再次核对源文件 signature + 内容抽样快照，封住“检查最新 -> 等待锁 -> 远端刚好发布”的并发窗口。

2. SketchUp 原生解锁/快速双击不能绕过
- 原生右键解锁仍不会自动取得 LinkHub 协作锁。
- 若空间不是最新，自动重新锁定并提示必须先更新/载入最新模型。
- 即使用户在锁监控下一拍之前快速双击进入空间层级，也会在 active_path 变化时立即退回根层级并重新锁定。
- 只有合法 LinkHub 编辑会话，或本版明确的“强制解锁恢复模式”，允许空间根保持解锁。

3. 新增“强制解锁”按钮
- 位于顶部“代/真模型切换”按钮右侧、“取消修改”按钮左侧。
- 只用于从本机当前已载入的历史/旧空间中复制、找回模型。
- 不要求当前模型是共享最新版本，因此可用于待更新/版本异常的历史空间救援。
- 不取得协同锁，不建立 editing 会话，不把旧模型标为最新。
- 强制解锁期间该空间禁止发布、更新、卸载、改名、删除。
- 批量空间更新会跳过处于强制解锁恢复模式的空间。

4. 强制解锁采用“快照 -> 临时解锁 -> 恢复”事务
- 进入前先把当前空间根 Definition 保存到 LOCALAPPDATA 下的独立恢复快照。
- 快照使用整文件 SHA-256 验证，单空间保留最近 3 份。
- 只解锁空间根，不批量改变内部组件锁，避免共享 Definition 被意外修改。
- 用户可在空间内复制需要找回的对象。
- 按 ESC 退出空间，或再次点击“强制解锁”，会载入进入前快照并替换回原空间 Definition。
- 强制解锁期间对空间内部的移动、删除、修改都不会作为正式修改保留。
- 恢复后空间根强制重新锁定。

5. 强制解锁期间发布被多层阻止
- request_space_publish / publish_space_now / publish_space_model 均有后端硬拦截。
- publish_space_model 在尝试退出 active_path 之前就检查强制恢复状态，不能通过发布动作顺带退出恢复模式。
- 强制恢复模式唯一合法出口是：ESC 或再次点击强制解锁 -> 恢复进入前快照。

6. 异常退出/保存保护
- 强制解锁状态与本机恢复快照路径写入当前项目状态。
- 如果用户在恢复模式中保存 SKP、异常退出或 SketchUp 崩溃，下次打开项目会检测未结束的强制解锁并优先自动恢复进入前快照。
- 若恢复快照缺失/损坏，空间保持锁定并继续禁止发布，不会猜测性覆盖共享模型。

7. 协同安全基线
- COLLAB_DATA_SAFETY_MIN_VERSION 提升到 0.13.6.18。
- 新版会提示仍由低于 0.13.6.18 的客户端写入的共享清单，避免老客户端继续绕过“编辑前必须最新”的保护。

建议使用流程
------------
正常工作：
待更新/待载入 -> 更新 -> 状态“已更新” -> LinkHub 修改 -> 发布。

历史救援：
选中本机已载入的旧空间 -> 顶部“强制解锁” -> 确认警告 -> 进入旧空间复制需要找回的对象 -> ESC -> 插件自动恢复旧空间到进入强制解锁前状态并锁定 -> 在安全位置粘贴复制内容。

注意：强制解锁不是“强制发布”。它刻意没有任何发布权限。
