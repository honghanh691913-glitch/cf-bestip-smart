SU LinkHub v0.13.6.115

硬装 / 软装跨工作区编辑与发布流优化

本版目标

- 工作区只负责“当前操作焦点”，不再把同一 SketchUp 会话已经取得的硬装/软装空间协作占用误当成随工作区切换而失效。
- 在视口中直接操作目标空间：跨工作区双击可就地确认并自动切换后进入修改；跨工作区发布可就地确认后直接发布，不要求来回切标签。
- 保持 LinkHub 现有的版本最新校验、协作锁、发布候选、后台发布、代理/真模型以及恢复机制，不通过放宽安全校验换取便利。

主要改动

1. 修复跨工作区后“协作占用已失效”的根因
- 硬装/软装空间锁的有效所有权改为“具体空间 + 当前 SketchUp 进程/会话”，不再以当前 UI 工作区是否与 actor_role 相同作为有效性条件。
- 当前工作区切换只改变导航焦点；同一 SketchUp 会话持有的软装/硬装锁仍继续有效，退出空间时不会再因为切过工作区而被误判失效、自动锁回。
- 发布成功或显式释放空间锁时，同一进程即使当前停在另一个硬装/软装工作区，也能正确释放该空间占用。
- 旧版本若曾把软装锁误重绑成硬装（或反过来），读取锁时会按空间自己的 collection_key 自动修复专业身份，并保留诊断记录。
- 建筑/景观原有的工作区安全边界保持不变，本次会话级锁语义只针对硬装/软装空间。

2. 跨工作区双击直接进入目标空间
- 根层级双击候选不再只识别“当前工作区 + 已锁定”的空间；任意已加载的受管硬装/软装空间根都可被准确识别，包括仍处于本机待发布、根组件保持解锁的空间。
- 在硬装工作区双击软装空间，鼠标附近显示“进入软装工作区？”的“是 / 否”小确认；软装双击硬装同理。
- 点击“是”：快速切换到目标工作区，然后继续执行目标空间原有的最新版本校验、协作占用校验、焦点切换与自动进入组件。
- 点击“否”或确认层外取消：不切工作区、不改锁、不改模型状态。
- 同工作区双击仍直接进入，不额外增加确认步骤。
- 家具双击确认继续沿用原有就地小确认层，现将该确认层泛化为统一的“就地确认”，不改变家具编辑事务。

3. 顶部快捷条支持选中跨工作区空间
- 顶部主按钮现在按“视口中明确选中的受管空间根”优先识别，不再因当前工作区不同而忽略目标。
- 选中另一个工作区的正常空间时，主按钮可进入修改；点击后使用原生确认框提示切换到目标工作区，再自动进入修改。
- 选中另一个工作区的本机待发布空间时，主按钮直接显示发布入口，不需要先切工作区。
- 代/真模型等专业内作用域功能仍使用原有“当前工作区过滤”，避免这次跨工作区优化意外扩大表示切换范围。

4. 跨工作区直接发布
- 如果当前位于硬装工作区，但选中的待发布空间属于软装（或反过来），点击发布会先明确提示目标属于哪个工作区。
- 确认后保持当前工作区不变，直接发布目标空间；发布成功后按原流程锁定目标、释放协作占用并进入后台发布收尾。
- 发布前仍必须满足：空间已取得本机协作占用、共享版本关系安全、根结构有效、非强制历史取物模式、非后台发布冲突状态等原有条件。
- 没有取得协作占用的空间不会因为“跨工作区发布”而获得绕过权限。

5. 多空间切换行为
- 从一个待发布空间转去另一个硬装/软装空间时，原空间的本地修改和协作占用继续保留；焦点切换继续走 LinkHub 既有的安全暂存/隔离流程。
- 工作区切换本身不强制做家具代理/真模型转换；表示状态继续由既有代/真按钮、发布和代理任务管理，避免因为导航而触发大型定义替换。
- 目标空间若不是最新共享版本、尚未载入、被他人占用或处于后台发布中，仍会在真正进入修改前被原安全校验阻止并给出明确原因。

验证

- runtime.rb Ruby 语法检查通过。
- 主入口 main.rb Ruby 语法检查通过。
- RBZ ZIP 完整性检查通过。
- 静态回归核对：跨工作区根识别、就地确认、自动切工作区编辑、跨工作区发布确认、空间锁会话所有权、旧错误 actor_role 自愈、跨工作区锁释放均已接入。
- 未改动空间发布的数据打包/原子覆盖、家具代理生成、最新版本校验、他人锁判断与强制历史取物安全边界。

建议重点实机回归

- 软装 A 修改中 -> 退出组件到世界根 -> 在软装工作区直接双击硬装 B -> “是” -> 自动进入硬装 B；随后退出 B，再双击软装 A，确认能继续进入且不出现“协作占用已失效”。
- 软装 A 修改中 -> 切到硬装工作区 -> 直接选中软装 A -> 顶部发布 -> 确认“直接发布软装空间” -> 发布成功，当前仍停留在硬装工作区，软装 A 占用正确释放。
- 在硬装工作区选中未修改的软装空间 -> 顶部修改 -> 确认切换 -> 自动进入软装；取消确认时任何状态均不改变。
- 其它成员正在占用目标空间、目标共享版本更新、目标后台发布中的情况继续被阻止。
