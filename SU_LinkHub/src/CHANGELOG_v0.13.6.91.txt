SU LinkHub v0.13.6.91
=======================

本版把 v0.13.6.87~90 的连续修复重新合并为一套一致的“空间编辑沙箱 + 空壳修复 + 待提交代理队列”状态机，重点解决用户实测仍出现的多层 PACKAGE/PAYLOAD 与 SketchUp“部分实例已锁定”三选一弹窗。

1. 空间编辑入口改为 Definition 编辑沙箱
   - 取得 LinkHub 协作锁后，先解锁当前空间根。
   - 当前空间根 Definition 只要还有其它实例共享，就只对当前空间根 make_unique。
   - 后续空壳 explode 因此只改变当前空间，不会把其它锁定空间/实例一起改掉。

2. 根因修复 SketchUp“部分实例已锁定”弹窗
   - 旧版只检查 definition.instances 中“其它实例是否直接 locked?”，这不足以覆盖嵌套父 Definition 的锁传播。
   - v0.13.6.91 改为：空间根到连续唯一核心层的编辑脊柱，只要 Definition 有第二个实例共享，就对当前节点 make_unique。
   - 每处理一层后再读取下一层，因此父级 make_unique 新复制出来的子实例也会被继续识别并隔离。
   - 不执行“全部解锁”，其它空间和其它实例的锁状态不变。

3. 修复 v0.13.6.90 双击桥遗漏
   - v0.13.6.90 虽然能识别 space_spine 候选，但 activate_workspace_double_click_bridge 仍只允许 soft_proxy 在 active_path 内通过，导致空间核心层桥接实际上无法激活，SketchUp 原生 SelectionTool 会先弹三选一。
   - v0.13.6.91 已同时放行 soft_proxy 与 space_spine 两类 LinkHub 明确管理的嵌套双击入口。

4. 空壳修复顺序重新调整
   - 旧流程是先清空壳、后清内部锁；历史 PACKAGE/PAYLOAD 如果本身带旧版 locked 标记，会被安全规则挡住。
   - 新流程先清理 LinkHub 空间内部遗留原生锁，再处理 PACKAGE/PAYLOAD，处理后再补扫一次内部锁。
   - LinkHub 明确认出的运输壳即使自身带历史 locked 标记，也只在 explode 前临时解锁该“即将删除的壳”；普通用户组件仍然不会因此被解锁或拆除。

5. 继续清理有 Definition 的历史运输壳
   - 继续识别 LH_SPACE_PACKAGE_* / H_SPACE_PACKAGE_* / SPACE_PACKAGE_*。
   - 继续识别受信任 PACKAGE 链中的 LH_SPACE_PAYLOAD_* / SPACE_PAYLOAD_* / PAYLOAD_*。
   - Definition 有名字和 LinkHub package 元数据不再成为保留运输壳的理由。
   - 真正业务核心（例如带“软装”Tag/名称/材质/行为/用户属性的内容层）继续保留。

6. 增加进入前验证
   - 编辑脊柱 make_unique 后会重新扫描。
   - 如果仍存在共享 Definition，LinkHub 会停止进入，不把控制权交给 SketchUp 原生“全部解锁/设为唯一”弹窗。
   - 双击核心层兜底也会在 active_path= 前验证当前 Definition 已经真正独立。

7. 保留 v0.13.6.87 的待提交代理可视化
   - 家具完成修改并退出单件组件后进入待提交队列，显示黄色半透明 3D 外包盒。
   - 多件家具可同时高亮；当前处理项更亮，失败项保留橙黄色提示。
   - 同款合并生成一次六面代理；每款成功后清掉对应 pending，高亮按队列逐个消失。

8. 保留统一代理队列触发
   - 完全退出空间到全模审阅：启动待处理代理队列。
   - 点击“代理”按钮：先安全退出工作空间，再启动待处理代理队列，完成后切换代理。
   - 点击“发布”：空间成功加入发布队列后启动待处理代理队列，并继续避开发布原生关键区。

9. 更新 / 修改 / 退出 / 发布的空壳维护继续保留
   - 空间更新载入后自动修复历史运输壳。
   - 点击修改进入前自动修复。
   - 退出空间到全模审阅时自动修复。
   - 发布前自动修复。
   - 家具真模编辑入口及写回模型库继续保留安全普通空壳修复与尺寸复核。

10. 安装说明
   - 本版修改了 ToolsObserver / 双击桥接行为。由 v0.13.6.90 升级时建议安装后完整关闭所有 SketchUp 窗口，再重新启动 SketchUp 一次，避免旧进程中的观察器继续占用原生选择工具。
